# Current PH-Composer UI reference points

These paths identify accepted patterns. Reinspect them before reuse and extract shared components when the behavior truly matches.

Paths under **Local** are in this repository at `src/ph_composer/html/`. The UI kit registers modules with `PhComposerUI.define` and uses the `phc-` class prefix. Paths under **Predecessor only** are in `../ph-navigator-sketchup/src/ph_navigator_sketchup/html/` and have not transplanted; they are reference points for screens this repository will build, not current files. The predecessor's Window Schedule, assigned-window propagation and designPH review screens do not transplant; their designPH-specific patterns are omitted here.

## Shared primitives (local)

- `workspace.js` is the `ui` facade over the shared layer; each part has one file: `dom.js` (elements, `svg`, `commandButton`, `memoPaint`), `icons.js` (the icon registry, which throws on an unknown name, icon buttons and state-aware icon painting), `overlay.js` (`Bubble`, `ActionMenu`, dialog action rows, `formDialog`, `floatingNotice`, tooltips), `table.js` (table presentation) and `view_controls.js` (filter, group and order controls, group headings; an optional `guard`/`refused` pair refuses a filter edit while a draft would be hidden).
- `page_header.js` `ui.pageHeader({ title, actions, primary })`: the one page header. Title, secondary actions, then the one filled primary action at the right, with no caption and no count: a record count lives in the control row, where it can say how many a filter leaves. Every pane opens with it; a screen never styles its own heading. `--page-gutter` in `base.css` is the one horizontal inset: the pane carries it, and a rule that separates page regions (the subtabs row) runs through it to the panel edge. `setTitle` renames it in place. A detached session that covers a work surface (the Window Type Installs editor) uses the same header, with Cancel as its action and Save as its primary, so both stay in view.
- `subtabs.js`: `refused(reason, nextId)` names the tab that was asked for and `reselected(id)` reports a click on the shown tab. An owner whose surface is covered by a session (Installs) uses both to leave that session the way its Cancel does: at once when nothing is staged, through the discard confirmation otherwise.
- Installs drawing (`features/windows/install_editor.js`): edge state is data in the selection teal, solid when assigned and dashed when it follows the Model default; missing is the warning ink; `--drawing-highlight-halo` marks hover and focus. Each edge has a wide transparent target under a thin stroke. A perimeter value is written outside its element, a shared edge carries one "0", and a value is dropped where its edge is too short. Escape unwinds the form, then the copy list, then the session, from wherever focus is.
- Window Types frame (`features/windows/placement.js`, `editor.js`, `windows.css`): the Place tool's one setting, its anchor, is an icon beside Place that opens the nine anchors as a three by three grid of setting choices; the placement row shows only while the tool is placing. Rail rows give their whole width to the name and lay their action icons over the row end on hover and focus. An Empty element carries a small "Empty" caption.
- Library sidebar (`library/sidebar.js`, `library/rows.js`, `library/library.css`): a title that folds the sidebar, small muted group captions with a rule, and borderless record rows that tint on hover. All three are buttons; none is drawn as one. Beside the table of the same records (`besideTable`), "In this file" shows one line pointing at the source select in place of a repeated list. A library's row ends in a plus glyph and says "Add <name> to this file"; the record's card stays the place where the copy is reviewed and committed. Group headings carry their count; a list of more than 20 records starts with its groups folded, a search opens what it finds, and a fold the user chose stays. The rail sits at the right in both Builders, because the Window Builder's left edge holds its Types rail. Before any library exists, the sidebar's setup button reads "Add a library…".
- Library setup (`library/setup.js`): leads with the first task. With no library yet, the two ways to add one (file, folder) show at once as choice cards, each one native picker; afterwards they wait behind "Add a library…". An added library is named in a success line and marked in the list, and Done becomes the primary. Every change applies at once, so the footer is Done, never Cancel. Agent access (approved locations) is a folded `details` beneath, saying that adding a library needs no approval.
- Record forms (`record_form.js`): `RecordForm.required(label, control)` marks a field the form waits for. A disabled Create says why in the form's status line, in the muted hint tone, not the error red. New Assembly has no form: it creates "Assembly N" and opens the Builder with the title selected (`features/assemblies/form.js`, `section.js`).
- Export readiness (`sections/export.js`): one status line ("Ready to export." or "Finish N things before exporting."), then findings grouped by cause under "Before exporting" and "Worth checking". A group shows its sentence once with the record id taken out, a count, one Locate for every record in it, and "Open <tab>" from `panel.tabFor`, which features feed with `panel.workedOn(prefix, tab)`. Record ids stay in the row's tooltip.
- Empty and unfinished: an inventory with no records names the next step ("No Assembly records yet. Choose + New Assembly."), and keeps "match this view" for a filter miss. Window Types with no Types shows one prompt and no product libraries. "Not finished" is the amber alert glyph with what is missing in its tooltip, on a row where the gap belongs (the Window Types rail, the Zone tree's cells, an Assembly's withheld U-value).
- Pane regions (`panel.js`): `main` is the work surface; `inspector` is one column beside it showing a single section, chosen by tier (`tool`, `selection`, `record`, `ambient`) among those whose `when(state)` is true, with `"hold"` keeping a section that carries a draft, and away when none is; `tools` are small controls the work surface places at the end of its control row with `panel.region(pane, "tools")`. A tool that opens an inspector section is an icon toggle with a stable name, pressed while its section shows, built once and repainted so a press keeps its focus. Under 900 wide the inspector drops beneath the work surface. The work surface never moves down for either.
- `panel.js` owns the snapshot reducer, the one floating notice and the tabs. `panel.notify(message, tone)` raises a page-side notice; `panel.navigationGuard(name, guard)` lets a section refuse a tab change while it owns work in progress; `panel.navigate(tab, intent)` opens another tab through those guards and hands `intent` to that pane's `onNavigate` sections. `request.js` gives each view a request channel with one correlated result; `snapshot.js` reads the host snapshot a render receives.
- `overlay.js` with `overlay.css` (bubbles, action menus, notices, dialogs) and `base.css` (the interaction tokens on `:root` and the shared subtabs nav). Pass `tone` to `notice.show`: omitted means `info` (white), `success` is white with a check and fades after `SUCCESS_MS` (3 s, held on hover or focus), `warning` is yellow, `error` is red; `data-tone` carries it to CSS. Host notices for a completed context-menu command use `:success`. Toolbar glyphs are Lucide outlines with the ISC notice kept beside them; take new glyphs from the same set. Classify each notice as transient or persistent: confirmations and ordinary information may fade on the next meaningful interaction; warnings, errors, and active-tool instructions remain until resolved or explicitly dismissed.
- One row of chrome above an inventory (`view_controls.js`, `inventory_grid.js`): the filter field, Group by, Order by, a sort-direction icon toggle, a muted count ("2 total", "1 of 2"; a screen may word it, as Zones / Faces does with "2 Zones"), a help button holding the keyboard hint, then the fill tools, which appear once a range of cells is selected and keep their place while idle so nothing moves. A tab's settings end the row. No row-number column: a row's position changes with sorting and filtering, so it is not a reference.
- A tree row with nothing under it keeps the chevron's place but offers nothing to open: give the table `expandable(row)`. A value a row still needs is flagged on its own cell: the enum pill turns amber, reads "?", and its accessible name says what to set ("Set Wall 2 boundary"). There is no separate State column: anything else the row needs (a stale adjacency, a missing Attached zone record) is flagged amber on the cell where it is fixed, with the reason in its tooltip.
- An enum cell is `select.phc-enum-cell` (`table.css`): a compact 24px pill with a chevron on every screen, neutral unless the value has a colour of its own through `--category-fill`. A value that cannot be chosen there (a paired Surface) is the same pill read only, `span.phc-enum-pill`, with what sets it in its tooltip. Face types and boundary conditions take a light tint of honeybee's display hue, the one the viewport's Colour-by modes draw: `face_words.fill(field, value)` or a `fill` on a `selectFields` choice, never a feature-local palette. Never style a select by its column name.
- A cell under a header that names a unit holds the number alone: `units.format(..., { showUnit: false })`.
- `table.js` and `table.css`: shared table behavior. A quiet grid: a hairline under each row and column separators only in the header. Hover washes the whole row over whatever each cell shows; it never tints one cell or borrows a chip's colour. `tree: true` makes top-level rows group headings (tinted, bold, a firmer rule above). Disclosure chevrons are borderless glyphs, named "Collapse Zone 1" rather than repeating the row's kind. Header-edge separators provide mouse and keyboard column resizing; double-click resets a width. The Table options menu is not built yet; when a table needs show/hide choices, they go in that anchored menu, not in-flow controls. Use the shared cell-input and editable-cell classes so the table grid supplies the resting boundary and the cell supplies interaction emphasis. Focus styles and resized widths must preserve sticky offsets and never move identity cells unexpectedly.
- `overlay.js` `formDialog(className, onCancel)` and the form-dialog class in `overlay.css`: the one modal. Its top-right close (`.phc-dialog-close`) calls `onCancel`, like Escape, and is put back on every open; closing returns focus to the opener. `record_form.js` is the lifecycle every record form shares: container, title, submit and Cancel order, status line, one single-flight request. `ui.table` passes the clicked row button as the third `action` argument so a bubble can anchor to the row that asked.
- Stylesheets, one owner each, linked in this order by `index.html`: `base.css` (tokens, page defaults, typography, shared controls and navigation), `overlay.css`, `shell.css` (the shell, the Export section and the status bar), `table.css`, `features/zones/zones.css` (the Zones / Faces screen, the Zone details form and the Colour-by legend). A screen's override of a shared primitive carries that screen's scope class so specificity, not link order, decides it.
- `unit_field.js` `UnitField`, `units.js`, `unit_preferences.js` and `fields.js`: every unit-bearing input and its stored-field descriptor.

## Accepted screen patterns (local)

- Zones / Faces: `features/zones/overview.js`, `features/zones/zones.css`. The Zone tree as a shared table, Face rows beneath their Zone, type and boundary edited in place as chips, Locate and Suggest classification as row actions. A Face with no record yet is a row too, under one "N unclassified Faces" summary row per Zone: open by itself at ten or fewer, closed above that, and showing its first fifty with a "Show all" row beyond. Choosing a type or a boundary on such a row classifies it. The inspector beside the tree shows, by tier: the Classify palette while the tool is in use; the Face selection (Type, Boundary and Assembly for every selected Face, each applied at once as one Undo step, a value they do not share reading "Mixed"); the selected Zone's fields as a form whose Save and Cancel appear once a field changes, and which holds the inspector while it has a draft. One draft at a time: while the form is dirty or its Save is pending, selecting another row, filtering and changing tabs are refused with a warning notice and focus returns to the form. In the inspector, Faces selected in the viewport outrank a Zone, but a Zone row the user clicks takes the inspector and keeps it until the viewport selection next changes (D9). The selection's Assembly control rests on the Assembly every selected Face shares and reads "Mixed" when they differ (D10).
- Attached-zone inline creation: `features/zones/attached_zone_assignment.js` and `features/zones/attached_zone_fields.js`. A `formDialog` opened from a Face's boundary chip; Cancel leaves the chip unchanged, a refusal keeps the draft, success closes and restores focus to the chip.
- A blocked primary action carries `ui.reasonButton(action, reason)` beside it: an alert icon named "Why <action> is unavailable" that opens the reason in an anchored bubble (Make Zone on Zones / Faces).
- Classify tool and palette: `features/zones/classify.js` in the panel and the viewport tool in `src/ph_composer/features/zones/faces/classify_tool.rb` with its native menu. The drawing-tool state rule applies: pressed control, icon and cursor change together, Escape unwinds one layer, and a refusal is a warning notice.
- Colour-by: `sections/colour_by.js`. The mode select is a tool in the work surface's control row; the legend is an inspector section shown while a mode is on. Rows come from the shared service's legend, so a new mode needs no line here.
- Export: `sections/export.js`. A running export locks tab changes through the navigation guard and keeps its progress and Cancel visible.
- Assembly Builder: `features/assemblies/editor.js`, `features/assemblies/canvas.js`, `features/assemblies/assembly.css`. Use for compact toolbars, header metrics, contextual inspectors, crisp drawings, insertion controls, and anchored editors.
- Library and library sidebar: `library/section.js`, `library/sidebar.js`, `library/library.css`. Use for browsing density, source status, filters, row selection, and collapsible sidebar behavior. The sidebar is provider-agnostic: it shows a provider's name and connection state, never its address.
- Library tabs: `library/section.js` and `features/windows/inventory.js`. One page heading for every tab, holding the active tab's "+ New" beside Export library; each tab body opens with the shared action bar (view controls, then tab settings) and keeps it to one line at 1280 px. Tab settings sit at the end of the action bar through the kit `Inventory`'s `settings` option, as compact controls that open a choice list (the current choice `aria-pressed`) or a single-value bubble; the Psi-Install Types Model defaults are the example. Record forms use `formDialog`; a record's uses open in a bubble anchored to its row action.
- Window Types: `features/windows/editor.js`, `features/windows/canvas.js`, `features/windows/windows.css`. Use for the page-header action hierarchy, title and metrics, floating notices, contextual drawing tools, selection treatment, edge inserts, single-value dimension bubbles and the adapted collapsible sidebar.

## Accepted screen patterns (predecessor only)

- Spaces table: `spaces_table.js`, `sections/spaces_workspace.js`, `cell_edits.js`, `spaces.css`. Use for tree tables, the Level rail, saved table layout, range edits and Locate.
- Consequential multi-step review: the assigned-window resize in `window_editor.js` and `windows.css`. Use the shared dialog treatment for a review the user must read before committing, including modal Escape cancellation and trigger-focus restoration without work-surface reflow. Only the dialog shape carries over.

## Shared visual semantics

- `--interaction-highlight`: interactive borders, selected controls, active sidebar rows and selected drawing elements.
- `--interaction-highlight-hover`: stronger hover and active emphasis.
- `--interaction-highlight-tint`: low-contrast selected backgrounds, including the selected drawing element fill.
- `--drawing-highlight`: drawing hover, keyboard focus, insertion geometry and drop targets; never selection.
- `--drawing-highlight-halo`: focused or hovered drawing affordance halo.
- `--line`, `--muted`, `--surface`: neutral structure and hierarchy.

Do not create a feature-local substitute for these semantics without evidence that the shared token is wrong app-wide.
