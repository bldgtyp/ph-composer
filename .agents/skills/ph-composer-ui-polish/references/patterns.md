# Current PH-Composer UI reference points

These paths identify accepted patterns. Reinspect them before reuse and extract shared components when the behavior truly matches.

Until the UI kit transplants, every path below lives in the predecessor at `../ph-navigator-sketchup/src/ph_navigator_sketchup/html/`. After the transplant the same file names live under this repository's `html/` folder, and the `phn-` class prefix and `Phn` registry name follow the namespace decision. The patterns are the same in both places. The predecessor's Window Schedule, assigned-window propagation and designPH review screens do not transplant; their designPH-specific patterns are omitted here.

## Shared primitives

- `workspace.js` is the `ui` facade over the shared layer; each part has one file: `dom.js` (elements, `svg`, `commandButton`, `memoPaint`), `icons.js` (the icon registry, which throws on an unknown name, icon buttons and state-aware icon painting), `overlay.js` (`Bubble`, `ActionMenu`, dialog action rows, `formDialog`, `floatingNotice`, tooltips), `table.js` (table presentation), `view_controls.js` (filter, group and order controls, group headings) and `domain_options.js` (stored enum chips and feature flags). The Spaces columns, values and row actions are `spaces_table.js`.
- `overlay.js` with `overlay.css` (bubbles, action menus, notices, dialogs), `base.css` (the interaction tokens on `:root` and the shared subtabs nav) and `library.css` (the Library sidebar patterns). Pass `tone` to `notice.show`: omitted means `info` (white), `warning` is yellow, `error` is red; `data-tone` carries it to CSS. The icon registry's drawing toolbar glyphs (`zoom_in`, `zoom_out`, `fit`, `clear`, `merge`, `split`, `glazed`, `empty`, `mirror`, `eyedropper`, `paint_bucket`, `undo`) are Lucide outlines with the ISC notice kept beside them; take new glyphs from the same set. Classify each notice as transient or persistent: confirmations and ordinary information may fade on the next meaningful interaction; warnings, errors, and active-tool instructions remain until resolved or explicitly dismissed.
- `table.js`, `record_edits.js`, `inventory_grid.js`, and `table.css`: shared table behavior. Header-edge separators provide mouse and keyboard column resizing for every `ui.table`; double-click and the Table options menu reset widths. Keep show/hide choices in that anchored menu, not in-flow controls. Use the shared cell-input and editable-cell classes so the table grid supplies the resting boundary and the cell supplies interaction emphasis; do not restore per-input boxes on individual table pages. Printable typing on a focused cell begins editing and preserves the first character. Focus styles and resized widths must preserve sticky offsets and never move identity cells unexpectedly. Per-cell validation keeps the invalid marker in the grid and presents its explanation in a focus/hover-anchored overlay, linked with `aria-describedby`, so errors remain local without resizing rows.
- `overlay.js` `formDialog(className, onCancel)` and the form-dialog class in `overlay.css`: the modal for record forms. `hidden` mirrors the open state, `openModal()`/`closeModal()` drive it, Escape runs the owner's cancel (which may refuse while a request is pending), and fields wrap into two columns at dialog width. `ui.table` passes the clicked row button as the third `action` argument so a bubble can anchor to the row that asked.
- Stylesheets, one owner each, linked in this order by `index.html`: `base.css` (tokens, page defaults, typography, shared controls and navigation), `table.css`, `overlay.css`, `spaces.css`, `shell.css` (the Overview and Export sections and the live panel's status bar), `assembly.css`, `library.css`, `windows.css`. A screen's override of a shared primitive carries that screen's scope class so specificity, not link order, decides it.
- `unit_field.js` `UnitField` and the dimension-format control: every unit-bearing input. The format control is a submenu row when given a "…" menu and a toolbar icon without one.

## Accepted screen patterns

- Assembly Builder: `assembly_editor.js`, `assembly_canvas.js`, `assembly.css`. Use for compact toolbars, header metrics, contextual inspectors, crisp drawings, insertion controls, and anchored editors.
- Library and library sidebar: `sections/library.js`, `library_sidebar.js`, `library.css`. Use for browsing density, source status, filters, row selection, and collapsible sidebar behavior. The sidebar is provider-agnostic: it shows a provider's name and connection state, never its address.
- Library tabs: `sections/library.js` and `window_inventory.js`. One page heading for every tab; each tab body opens with the shared action bar (view controls, tab settings such as the Psi-Install model default, then "+ New") and keeps it to one line at 1280 px. Table aggregates ("8 records · 29 element uses") sit muted in the grid toolbar beside Table options. Text columns align left. Record forms use `formDialog`; a record's uses open in a bubble anchored to its row action; the Source column maps definition source kinds to glossary words.
- Window Types: `window_editor.js`, `window_canvas.js`, `windows.css`. Use for the page-header action hierarchy, title and metrics, floating notices, contextual drawing tools, selection treatment, and the adapted collapsible sidebar. Its section tabs use the shared subtabs nav. Header: `headerMetric` (U<sub>w</sub> / U<sub>w,installed</sub> labels carrying the unit, `paintMetric` for the missing-value glyph plus a what-is-missing tooltip, a hover info bubble), `renameInline(record, anchor)` (header title or sidebar row edited in place with check and cross, mousedown suppressed so blur cannot pre-empt cancel), `renderList` row actions (Rename, Duplicate, Delete revealed on hover), `createType`/`duplicateType` (immediate, `uniqueName`, then rename) and `paintReadiness` (the "Before placing" alert beside Place mapping calculation findings to steps). The viewing side is a `ui.chipOptions` select ("Exterior view" / "Interior view"), the same enum chip as the Assembly Builder header; use that chip for any named-state choice instead of a button whose label changes. Element cards keep reading order; a selection hides the other cards and a filter row offers "Show all elements". Each card is a compact element grid (`CARD_COLUMNS`, `bare()` for unit-free cells, a product select with a CSS chevron, a star reference toggle) and `elementFindings` returns missing inputs keyed by row, painted as incomplete rows with an alert icon. Edge inserts: `window_canvas.js` `edgeTargets` (visual edge to canonical index, Interior mirroring, up-front refusal text) and `edgeInserts` (hover-revealed insert controls), with `window_editor.js` `insertBand` applying the default and selecting the new elements. Row and column sizes: `window_editor.js` `dimension` (single-value bubble with a `UnitField` using `commitOnBlur` and `onCommit`, the same shape as the Assembly Builder layer thickness) and `confirmBandRemoval` (a `formDialog` confirm naming the removed elements).
- Spaces table: `spaces_table.js`, `sections/spaces_workspace.js`, `cell_edits.js`, `spaces.css`. Use for tree tables, the Level rail, saved table layout, range edits and Locate.
- Consequential multi-step review: the predecessor's assigned-window resize in `window_editor.js` and `windows.css`. Use the shared dialog treatment for a review the user must read before committing, including modal Escape cancellation and trigger-focus restoration without work-surface reflow. The predecessor's review was designPH-bound; only the dialog shape carries over.

Record each here once the owner accepts a screen.

## Shared visual semantics

- `--interaction-highlight`: interactive borders, selected controls, active sidebar rows and selected drawing elements.
- `--interaction-highlight-hover`: stronger hover and active emphasis.
- `--interaction-highlight-tint`: low-contrast selected backgrounds, including the selected drawing element fill.
- `--drawing-highlight`: drawing hover, keyboard focus, insertion geometry and drop targets; never selection.
- `--drawing-highlight-halo`: focused or hovered drawing affordance halo.
- `--line`, `--muted`, `--surface`: neutral structure and hierarchy.

Do not create a feature-local substitute for these semantics without evidence that the shared token is wrong app-wide.
