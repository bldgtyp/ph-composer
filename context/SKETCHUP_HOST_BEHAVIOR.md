# SketchUp host behavior: measured facts for agents

**DATE:** 2026-09-30

Unless a row says otherwise, every fact here was measured in the predecessor, PH-Navigator for
SketchUp, on SketchUp Pro 2026.1 build 26.1.188 (macOS, embedded Ruby 3.2.2) between 2026-09-06 and
2026-09-17, through its development host bridge. Rows marked "Measured in PH-Composer" come from this
repository's own bridge on the same host. designPH 2.2.29 was installed and loaded on that host throughout.
Re-measuring the observer-ordering facts on a host without designPH is a pending gate for this
project; until then treat them as likely and pin them in the stub as the predecessor did.

Each fact names the code that depended on it and the offline test or stub rule that pinned it in
the predecessor. Tests for facts this repository already depends on were ported and are named
in the Pinned by column; tests named for Volumes, Spaces and `GeometryReference` are the
predecessor's and move here with the Spaces feature. When a fact changes on a newer
host, update the stub and this file in the same change. The full record, including the designPH
and Dynamic Components facts this file drops, is
[`../../ph-navigator-sketchup/context/SKETCHUP_HOST_BEHAVIOR.md`](../../ph-navigator-sketchup/context/SKETCHUP_HOST_BEHAVIOR.md).

## Observers and edit contexts

| Fact | Consequence | Pinned by |
| --- | --- | --- |
| Observer callbacks for one user action arrive after the Ruby call that caused them returns, and in a fixed order: `onTransactionCommit`, then `onActivePathChanged`. On leaving a Volume with Escape (or `Model#close_active`), the commit callback arrives with `active_path` already outside the Volume. | A reconciler that rebaselines on commit loses the Volume it needs to protect. Either callback must queue the exit protection from the baseline. | `test_exit_protects_when_commit_arrives_before_path_change` |
| For an operation Ruby opens and commits itself, `Model#commit_operation` delivers `onTransactionCommit` synchronously, before the call returns. Measured in PH-Composer on 26.1.188, 2026-09-18. | The session recognizes its own commit inside the operation; it still handles a callback that arrives later. | Stub `Model#commit_operation`; `tests/sessions_test.rb` |
| `Model#abort_operation` fires `onTransactionUndo`, synchronously, and no `onTransactionAbort`. Measured in PH-Composer on 26.1.188, 2026-09-18. | An observer cannot tell an aborted operation from a user Undo by the callback alone. The session ignores the Undo callback inside its own operation, so a rolled-back change leaves the revision. | Stub `Model#abort_operation`; `test_abort_reports_an_undo_as_the_host_does` |
| Leaving or entering a group edit context is itself a transaction: `onTransactionCommit` fires on Escape, and a context change marks the Model modified. | Do not read a commit as "geometry changed"; a save followed by a context close leaves the title marked modified. | Recorded; no stub rule |
| Inside `onPreSaveModel`, `Model#active_path` is empty although the edit context is still open on screen. SketchUp restores the context after the save. | Pre-save work cannot read the Volume from the path; the reconciler uses its baseline Volume. | Stub `Model#save` (`fire_pre_save`) |
| Setting `Model#active_path` inside `onPreSaveModel` makes SketchUp serialize the reopened context in world coordinates: the reopened file has the Space transform baked into its Volumes. In memory nothing has moved. | Never change the path during pre-save. Protect in `onPreSaveModel`; close the boundary in `onSaveModel`. | Stub `Model#save` raises on a pre-save path change |
| `onSaveModel` fires after the file is written, on the restored path, with `modified?` false. | The right moment to close a boundary the save left open. | Stub `Model#save` fires it |
| While a context is open, the API reports `Group#transformation` of entities on the active path in world coordinates, not relative to their parent. Closing the context restores relative values. | Compare against stored home transforms only through a path-aware transform reader; a raw comparison reports `volume_moved` for every open Volume. | `GeometryReference` tests |
| Opening a repeated parent context rebases shared child transformations, and `Sketchup::InstancePath#transformation` can then return a wrong position for another occurrence of that parent. | Withhold world geometry for shared definitions while their edit context is open, or compensate with the current raw root-to-leaf transform. | Predecessor window reader phases 3a and 3b1 |
| After `Model#active_path=` opens a Volume inside a Space that sits in a rotated plain group, `View#zoom(face)` frames that face correctly. A screen box computed from `edit_transform` times the entity's reported bounds disagreed with the capture. | Zoom the target entity directly; judge framing from a capture, not from coordinates computed inside an open context. | Predecessor Spaces table controls, phase 4 |
| `Selection#add` of an entity outside `Model#active_entities` does nothing and raises nothing. | Selecting a sibling Volume from inside another Volume needs the context closed first. | Stub `Selection#add` ignores out-of-context entities |
| `Model#active_path=` from Ruby is honored outside save callbacks and fires `onActivePathChanged` later, not synchronously. | Read state in a later call; a `sleep` in the same call blocks the UI timers that deliver callbacks and run deferred work. | Bridge usage rule |
| `Model#close_active` delivers the same observer sequence as Escape. | The bridge can exit contexts without keystrokes. | Host gate 2026-09-06 |
| `View#pick_helper`'s `path_at` answers relative to the open edit context, not from the Model root: with a Group open, a Face inside it picks as a one-entity path. A pick over geometry outside the open context returns no hits at all. Measured in PH-Composer on 26.1.188, 2026-09-20. | A tool builds an occurrence reference by prepending `Model#active_path` to the picked path, which is unambiguous because nothing outside the context can be picked. Without it, every Face read as being in no Zone while the user was inside the Zone. | `Pick.face_path`; `test_a_pick_inside_an_open_edit_context_still_names_the_zone` |
| `OverlaysManager#add` accepts an overlay and leaves it disabled: it appears unticked in the Overlays panel and `draw` is never called. Measured in PH-Composer on 26.1.188, 2026-09-20. | An overlay must set `enabled = true` after it is added, or it draws nothing at all. Colour-by drew nothing on a real host until this was found. | `ColourBy::Service#attach_overlay`; `test_turning_a_mode_on_adds_one_overlay_and_turning_it_off_removes_it` |
| A fill drawn with `View#draw` exactly on the Face it colours z-fights with that Face, and the host blinks between the two as the camera moves. Measured in PH-Composer on 26.1.188, 2026-09-20. | Lift every drawn point toward the camera by a pixel or two, scaled through `View#pixels_to_model` so it holds at any zoom. | `ColourBy::Tessellation.lift`; `test_every_drawn_point_is_lifted_off_the_face_toward_the_camera` |
| A tool callback's `flags` carries `CONSTRAIN_MODIFIER_MASK` (131072) for Shift on macOS, and it is set on `onLButtonDown`: a plain click arrived as 2 and a Shift-click as 131074. `COPY_MODIFIER_MASK` is 524288 and `ALT_MODIFIER_MASK` 1048576. Measured in PH-Composer on 26.1.188, 2026-09-20. | Read the named constant rather than a literal, and test the mask on the button event rather than on the move. | Stub `host.rb` masks; `test_shift_click_takes_the_connected_coplanar_faces_and_stops_at_the_plane` |
| There is no `Sketchup::Model#active_tool`, although the offline stub has one. Measured in PH-Composer on 26.1.188, 2026-09-20. | Ask a tool whether it is active; do not ask the Model what is. | Stub deviation, `tests/support/sketchup/model.rb` |
| A custom tool does not receive SketchUp's double-click-to-enter-group: entering a Group belongs to the Select tool, as it does for every native drawing tool. Escape unwinds one layer per press, the active tool first and the edit context second. Measured in PH-Composer on 26.1.188, 2026-09-20. | A viewport tool reaches geometry inside a Group through the picked path rather than by opening it, and does not try to restore a navigation gesture the host reserves. | `tools/examples/authoring/classify_tool_walkthrough.rb` |
| SketchUp selects the entity a right-click landed on before it builds the context menu, and at the Model root that is the Group, not the Face inside it. Measured in PH-Composer on 26.1.188, 2026-09-20. | A context-menu handler decides what to offer from the selection, and an item that applies to Faces is offered inside the Group's context, not at the root. | `Zones::Faces::ClassifyMenu.classifiable?`; `test_the_context_menu_offers_the_palette_over_a_face_and_not_elsewhere` |

Measured in PH-Composer on 26.1.188, 2026-09-20: a pick over one Face returned five paths, the Face fourth. | Walk the hits and take the first path whose leaf is the kind wanted, rather than trusting `best_picked` or index 0. | `Pick.face_path` |
| A camera set from Ruby is not visible to `View#pick_helper` until the frame has been drawn, so a pick in the same call as a `zoom_extents` or a `camera=` picks against the old camera and can return nothing. Measured in PH-Composer on 26.1.188, 2026-09-20. | Change the camera in one bridge call and pick in a later one, as with every other deferred host callback. | `tools/examples/authoring/classify_tool_walkthrough.rb` `look` and `screen_points` |
| `View#write_image`, which the development bridge's `shot` uses, renders Model geometry only: no overlay, no tool drawing and no viewport HUD. Measured in PH-Composer on 26.1.188, 2026-09-20. | Visual evidence for an overlay or a tool needs a real window capture, not a bridge screenshot. A blank `shot` is not evidence that an overlay is broken. | `tools/hostkit/host_helpers.rb`; the D6 gate |
| With `model.active_path` inside a group, face vertices transformed by `model.edit_transform` give world geometry, while `InputPoint#position` is in active-context coordinates. | Transform a picked point to world coordinates for preview and containment. | Predecessor phase 7b2 |
| A component placed in a parent mirrored on X and scaled 1.5 by 0.75 measured its intended size after Redo and reopen only when its world placement transform was converted through `model.edit_transform.inverse` before `active_entities.add_instance`. Without that conversion the parent scale applied twice. | Keep preview and containment in world coordinates and compensate exactly once at the `add_instance` boundary. | Predecessor phase 7b2 |
| A Group's attribute dictionaries live on the Group, not in its definition. `group.set_attribute` writes to the instance, and two instances of one definition therefore carry separate dictionaries over one shared set of entities. Measured in PH-Composer on 26.1.188, 2026-09-20. | This is why a copied Zone has its own Zone record and the *same* Faces. Anything stored per occurrence goes on the Group; anything stored on a Face is shared by every occurrence of the container. A per-occurrence Face record is not possible without making the container unique. | `Occurrences.shared_storage?`; `test_repairing_a_copy_that_shares_its_faces_refuses_and_leaves_both_alone` |
| A Face built by `Entities#add_face` takes its normal from the winding of the points it is given, by the Newell method. Measured in PH-Composer on 26.1.188, 2026-09-20, when a Face drawn to split a wall came back facing the wall's own direction. | Code that reads a newly drawn Face's orientation must pass points wound the way it wants, and must not assume a default. The stub derives the normal the same way, so a fixture that omits one gets the normal its own points imply. | Stub `Face.newell_normal` |
| `Face#area` is already net of the Face's inner loops. Measured in PH-Composer on 26.1.188, 2026-09-20: a 12 m2 wall cut with a 4 m2 island reported 8 m2. | Never subtract hole areas again on top of the host's number. The offline stub subtracts inner loops for the same reason. | Stub `Face#area` |
| Copying a Group does not copy what is inside it: both Groups become instances of one definition and share every entity in it, while each instance keeps its own attribute dictionaries. `Group#definition.instances` then reports both. Measured in PH-Composer on 26.1.188, 2026-09-20. | A copied Zone has a duplicated UUID and shared members at the same time. Storage is shared whenever a container is a ComponentInstance **or** its definition has more than one instance; treating only the first as shared let a repair of the copy rewrite the original's Faces. | `Occurrences.shared_storage?`; stub `GroupDefinition`; `test_a_zone_copied_the_way_sketchup_copies_one_reads_as_shared_storage` |
| Opening one placement of a shared Group for editing gives that placement its own definition. Measured in PH-Composer on 26.1.188, 2026-09-30: two placements of one child Group held Face 48922; after native Edit Group on one, their definitions were 8052 and 8565 and their Faces 48922 and 49058. | A shared Face cannot be reached by a native right-click inside an opened Group, because opening it ends the sharing; the selection menu then correctly offers classification. The shared-storage refusal is reachable only through explicit references, such as the public operations with an occurrence path. | `features/zones/faces/selection.rb`; `tools/examples/authoring/corrections_walkthrough.rb` `r01_check` |
| `Group#entities` returns a new Ruby wrapper on every call, and two placements of one definition give wrappers that are neither the same object nor `==`. Measured in PH-Composer on 26.1.188, 2026-09-30. | Test shared storage by comparing `definition`s or `definition.instances.length`, never `entities` identity. | `Occurrences.shared_storage?`; `corrections_walkthrough.rb` `r01_check` |
| There is no `Sketchup::Model#undo`. Native Undo and Redo are menu actions, reached with `Sketchup.send_action("editUndo:")`, and they run on the UI queue rather than before the call returns. Measured in PH-Composer on 26.1.188, 2026-09-20. | Host code sends the action and reads the result in a later call. The offline stub keeps `Model#undo` because a test has no UI queue to run an action on, which is a deviation, not the host's API. | `test_the_stub_steps_undo_itself_because_the_host_has_no_model_undo`; the walkthroughs under `tools/examples/authoring/` |
| Drawing a coplanar outline onto a Face splits it and the original Face object keeps its `persistent_id` and every attribute dictionary; each further piece is new. An outline sharing part of the Face's boundary leaves separate Faces, while one wholly inside it leaves a single Face carrying a hole, whose `Face#area` is already net of that hole. Measured in PH-Composer on 26.1.188, 2026-09-20. | The adjacency solver reads the container after the cut and matches pieces by outline and surviving persistent id rather than assuming which is which. Its sliver thresholds judge area per Face the host will make, so a ring is judged whole and disjoint pieces separately. | `Zones::FaceSplit`; `tests/support/sketchup/split_model.rb`; `tools/examples/authoring/cut_walkthrough.rb` |
| A coordinated clean partition supports two 6 m² Faces against one 12 m² counterpart and one full-height Zone beside two stacked Zones on SketchUp 26.1.188. | Capture the original plane and local normal before drawing; validate actual pieces and write reciprocal records in one operation. Native rollback, Undo/Redo and fresh reopen preserve the complete result. | [P1-D multi-neighbour evidence](../planning/archive/phase-01-faces-and-zones/evidence/p1-d-multi-neighbour-adjacency.md) |
| Grouping stamped Faces takes their bounding Edges with them: the restored Group returned `manifold? == true` with 6 Faces and 12 Edges and nothing left in the parent context. Measured in PH-Composer on 26.1.188, 2026-09-20. | Limited Restore passes only the stamped Faces and lets the host collect the Edges. | `Zones::Repair.restore_plan`; `tools/examples/authoring/repair_walkthrough.rb` |
| SketchUp cut and paste can replace a `persistent_id`. | A durable UUID in PH-Composer's own dictionary survives the operation when the object is still logically the same; placement references stay path-qualified; session `entityID` is never durable identity. | Predecessor B2 evidence |
| `Sketchup::Model#delete_attribute` returned `nil` without removing the key. Deleting the key from `model.attribute_dictionary(namespace, false)` succeeded. | Remove Model-level keys through `AttributeDictionary#delete_key`, and model this in the stub. | Predecessor phase 6c2 |
| `Model#guid` changes across reopen. Persistent ids remain stable. Subnanometre floating-point differences also appear across reopen without a meaningful Model change. | A durable fingerprint uses persistent ids and normalized floats. Never use runtime Model or definition GUIDs as durable identity. | Predecessor phase 6c2 |
| Walking shared definition geometry once and hashing each occurrence path and transform separately reduced a 44-window Model fingerprint to 32,502 items in 103 slices; expanding definitions per occurrence was unacceptably large, and running the scan synchronously during Export blocked SketchUp before progress or cancellation. | Separate graph identity from occurrence placement in large Model walks, and run them under a bounded cancellable task. | Predecessor phases 6c2 and 6d |

## Process lifecycle on macOS

| Fact | Consequence |
| --- | --- |
| `open -a "SketchUp 2026"` fails; the bundle path works: `open -a "/Applications/SketchUp 2026/SketchUp.app" <model>`. | The bridge launcher uses the bundle path. |
| `Model#close` raises "Only the active model can be closed" for any other open Model. `Sketchup.file_new` fires `onNewModel` for the new document but leaves `Sketchup.active_model` on the previous one until the new window activates, which did not happen while SketchUp was in the background. Measured in PH-Composer on 26.1.188, 2026-09-18. | Drive a multi-document check by closing the active Model; never assume `file_new` switched the active Model. |
| Launched with no document, SketchUp waited at its Welcome screen and no bridge or extension code ran within two minutes. Observed once in PH-Composer on 26.1.188, 2026-09-18. | `host_bridge.py launch` always opens a Model. |
| A killed SketchUp restores its previous documents on the next launch, so the requested file may not be the active Model. | Quit cleanly: discard-save a modified Model to a scratch path, then `Sketchup.send_action("terminate:")`. Verify the active Model's file name. |
| AppleScript `tell application "SketchUp 2026" to quit` did not complete from a terminal; `terminate:` through the bridge does. | Do not use AppleScript to quit. |
| `osascript` System Events keystrokes to `process "SketchUp"` work once Accessibility is granted. `screencapture -x` captures the whole screen. | Send keys only to SketchUp. For evidence, prefer `View#write_image` for the viewport and a window-by-title capture for one SketchUp window. |
| A SketchUp window on an inactive macOS Space is absent from the on-screen window list, and a capture taken while it is being switched away comes back blank with the title bar intact; the bridge and the panel DOM keep working. | Treat a blank or missing capture as a Space or lock-screen condition, not a panel failure. Do not `activate` SketchUp to force it. |
| The first bridge launch after a clean quit sometimes brought SketchUp up without the bridge; the next launch found the process, could not quit it within 30 s, killed it, and the relaunch loaded normally. | Treat a launch that ends with "SketchUp not running" and no bridge as retryable. |
| `open` immediately after a kill can fail with `LSOpenURLs ... error -600` while the process is still exiting. | Wait for the process to disappear, then retry. |
| SketchUp has one Plugins folder per major version; a `.rb` file placed there loads at startup. | The bridge is installed there and never in the RBZ. |
| A launch fails while the Mac screen is locked. | A gate needs an unlocked screen. |
| A host check can fail because SketchUp is running with no Model open, which looks the same from outside as a running idle process. | Verify an active Model, not just a live process, before reading a gate result. |

## The panel's embedded browser

| Fact | Consequence |
| --- | --- |
| SketchUp's public `UI` API exposes no colour chooser, and an `<input type="color">` in an HtmlDialog opened no native chooser on this host. | A colour control has to be drawn in the panel. | An 8-percent background tint fading in 200 ms was effectively invisible as a context-change cue; a 200 ms list fade with 4 px movement plus a separate 650 ms primary-blue outline fade was visible. | Use the measured cue for context swaps only; honor reduced-motion preferences. |

## Components, glue and edge attributes

Measured in PH-Composer on 26.1.188, 2026-09-18 ([B3](../planning/archive/phase-00-foundation/evidence/spike-window.md), [B4](../planning/archive/phase-00-foundation/evidence/spike-edge.md)).

| Fact | Consequence |
| --- | --- |
| A glued `cuts_opening` component opens its host face in the view but leaves the face's loops unchanged. `Face#area` then subtracts each pane that lies wholly inside the face at its full area, so overlapping panes count twice, and subtracts nothing for a pane crossing the face boundary. | Never read net area from `Face#area`; derive openings from unit outlines and the gross outer loop. |
| After a host face is split, glued instances stay glued to the original face even when they lie wholly on the new one, and the new face is not cut. After an explode, `glued_to` can name an unrelated scrap face that still reports valid. | Verify glue geometrically: coplanar, containing the unit's outline. |
| `no_scale_mask` hides the Scale tool's handles; `Transformation` scaling from Ruby applies anyway. | Detect scaling from `xscale`/`yscale`; a mirror from a negative determinant. |

Undo, Redo and save and reopen restore dictionaries and ids exactly. | Edge tags multiply rather than vanish; a Model-level registry and a scan tell a split from a copy or a replacement. |

Measured in PH-Composer on 26.1.188, 2026-09-20
([P1-A](../planning/archive/phase-01-faces-and-zones/evidence/p1-a-geometry.md)).

| Fact | Consequence |
