# Assembly Builder parity matrix: predecessor vs Composer

DATE: 2026-10-04
STATUS: audit draft (static source read only; no host run, no hover or pixel checks)

Scope: UX-014 to UX-018 in `../REQUESTS.md`. designPH push, adoption and usage-scan affordances are an intentional exclusion (retired).

Path shorthand. PRED-JS = `ph-navigator-sketchup/src/ph_navigator_sketchup/html/`, PRED-RB = `ph-navigator-sketchup/src/ph_navigator_sketchup/features/assemblies/`. COMP-JS = `ph-composer/src/ph_composer/html/`, COMP-RB = `ph-composer/src/ph_composer/features/assemblies/`. Predecessor has no `commands/segments.rb`; segment commands live in `PRED-RB commands/layers.rb`. A bare `file:line` is in the same tree as the row's column. Predecessor action names are `assemblies.<verb>` (`PRED-RB actions.rb:61-86`); Composer sends `ph_composer.assemblies.assemblies.layers.<verb>` and `.segments.<verb>` via `COMP-JS features/assemblies/editor.js:125`, registered at `COMP-RB declarations/layers.rb:23`.

## Answers to the three questions

1. Edge-hover plus controls do not exist in Composer. They are absent, not hidden by CSS or a hit-target. No file under `COMP-JS` contains `insertion`, `add-layer`, `add-segment`, `near-` or a `mousemove` handler for the Builder (grep of the whole html tree finds mousemove only in `table.js:112,118`, `library/drag.js:39` and `features/windows/canvas.js:246`). `canvas.js` only draws SVG rects and the air-barrier line (`canvas.js:139-180`). `stage.js:63-81` builds one plain hit button per segment and nothing else. The only wiring left behind is `onDragChange` in `library/drag.js:75,102`, which the Builder never sets (`editor.js:38-63`). Composer already has a working edge-proximity pattern for Windows to reuse (`features/windows/canvas.js:202-266`).
2. Today in Composer: layer thickness is edited by clicking the thickness label in the left dimension column, which opens a bubble with a UnitField plus Apply and Cancel (`stage.js:23-38`, `editor.js:146-170`); Enter or Apply sends `layers.update {layer_id, thickness_mm}` (`editor.js:190-208`, `stage.js:30-32`). Segment width is edited by selecting a segment, then using the "Selected width" lane under the drawing (UnitField plus Apply and Cancel), which sends `segments.update {layer_id, segment_id, values:{width_mm}}` (`stage.js:82-91`). There is no drag handle and no inline blur-commit (blur keeps the draft, `tests/assembly_builder_test.js:194-207`). Membrane layers show a "Membrane" label and no width lane (`stage.js:26-28,83`).
3. Predecessor dimension lines are not SVG. The SVG holds only segments and the air-barrier line, with classes `assembly-segment`, `is-membrane`, `is-null-material`, `is-air-barrier`, `is-selected`, `assembly-air-barrier` (`assembly_canvas.js` render, about lines 91-159; hatch pattern `phn-null-material-hatch`). The dimensions are HTML divs styled by CSS. Layer thickness: column `.assembly-dimensions` 104px wide (`assembly.css:138-139`); one `.assembly-dimension` cell per layer sized `heightMm * zoom` (`assembly_stage.js:10-13`); `::before` draws a vertical rule at `right:12px` over the full cell height and `::after` a 16px horizontal tick at `right:4px, top:0` (`assembly.css:142-144`); the value button (white background, 80px, 11px text, right aligned, `margin-right:20px`) sits left of the rule (`assembly.css:112-113,140-141`); membrane cells read "Membrane" in muted text (`assembly.css:66`). Segment width: `.assembly-width-dimension`, shown only for the selected non-membrane segment, 16px high, placed `heightMm*zoom + 30px` below the drawing and spanning exactly that segment (`assembly_stage.js:167-175`); a 1px top border is the dimension line, `::before` and `::after` are 16px end ticks (`assembly.css:115-118`); the label button sits above the line, centered when the span is 90px or more (`.is-centered`), otherwise offset right with a 18px leader (`.is-narrow` and `::before`, `assembly.css:120-122`), flipped left by `.label-before` near the right edge (`assembly.css:145-146`, `assembly_stage.js:174`); the line is `pointer-events:none`, only the label is live (`assembly.css:115,119`). Library rail default: on the left of the editor (`sections/assemblies.js:89` appends the sidebar before the editor; `library.css:33` border-right), width 280px, and collapsed state is not fixed: `collapsed === null` resolves to `window.innerWidth < 900` (`library_sidebar.js:111`), so it is expanded at 900px or wider and a 36px vertical strip below that (`library.css:88-89`). When an Assembly opens its category groups start collapsed (`sections/assemblies.js:234`, `library_rows.js:43`). The S7 screenshot of a collapsed left rail is consistent with a narrow dialog, not a fixed default. Composer uses the same width rule (`library/sidebar.js:20`) but places the rail on the right (`editor.js:63-65`, `library/library.css:72`) and opens groups expanded (`library/rows.js:35,37`).

## Gaps to fix

Ordered by user impact. Each fix keeps Composer's accepted contracts (`expected_values`, undo names, honeybee vocabulary).

1. Edge-proximity add controls (UX-014). Add a pointer-near-edge plus control for layers (top and bottom edge of each layer, labelled "Add layer above" and "Add layer below" by orientation) and segments (left and right edge of each non-membrane segment), sending the existing `layers.add {anchor_layer_id, side}` and `segments.add {layer_id, index}`. Fix in `html/features/assemblies/stage.js` (build layer and segment targets after `stage.js:63-81`), `html/features/assemblies/assembly.css` (circle, highlight bar, z-index above `.assembly-hit-target`), reusing the logic of `html/features/windows/canvas.js:202-266`; wire `sidebar.onDragChange` in `editor.js` so controls hide during a drag.
2. Select the inserted segment or layer after add. Track the added id as the predecessor does (`assembly_editor.js:60-63,107-110`). Fix in `editor.js` `action` and `refresh`; no Ruby change (result ids are in the snapshot).
3. Segment add side. Expose left and right (index before or after) from the toolbar or the new edge controls; the toolbar "Add segment" currently always appends (`inspector.js:65`). Fix in `inspector.js` by passing `index` from the selection.
4. Dimension lines (UX-015). Draw the rule and 16px ticks per layer in the thickness column and an anchored width dimension under the selected segment, with narrow-segment leader. Fix in `assembly.css:46-49,61-62` (pseudo-elements as in the predecessor `assembly.css:115-123,142-151`) and `stage.js:82-91` (position the lane by `entry.xMm*zoom` and `entry.widthMm*zoom`).
5. Direct label editing. Let the width and thickness labels turn into inputs in place with Enter commit and Escape cancel; keep Apply for blur-safe drafts. Fix in `stage.js` and `editor.js:146-208`; preserve the draft guards tested in `tests/assembly_builder_test.js:103-135,194-207`.
6. Library rail. Choose side and initial state (UX-018): move the rail left in `editor.js:63-65` plus `assembly.css:2-3` and `library/library.css:72`; open groups collapsed on first open of an Assembly in `library/rows.js:35,37`. Decide whether the 900px width rule stays.
7. Library filters. Add category multi-select, sort select and a Clear button to `library/sidebar.js` and `library/rows.js:6-36`, using material category tone classes already in `features/assemblies/materials.js:8-9` and `library/library.css:11-17`.
8. Chips with semantic colour (UX-017). Style the type and exterior selects in `header.js:26-31` with tone classes keyed on the honeybee values; add tone maps beside `features/assemblies/form.js:4-10` and CSS in `assembly.css`.
9. Surface-film notes (UX-017). Keep the orientation-aware placement; add the exterior condition and a style per condition in `stage.js:7-12` and `assembly.css:43`.
10. Click-to-deselect on the selected segment and a swatch plus "Esc to deselect" hint. Fix in `stage.js:65-67` and `inspector.js:53-60`.
11. Segment-level read-only material properties in the settings bubble (conductivity, density, specific heat, emissivity). Fix in `inspector.js:88-111`, reusing `library/rows.js:119-123`.
12. Assembly information bubble (findings, usage, caption "Films ISO 6946 ..."). Fix in `header.js`; thermal data already in `record.display.thermal`.
13. Hover-open for the thickness bubble (predecessor `hover:true`). Pass `hover: true` at `stage.js:33`; the option exists at `overlay.js:31`.
14. Delete-layer entry point on the dimension bubble so it does not require a selection. Optional; Composer already offers it under Layer tools.
