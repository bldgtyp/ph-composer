# SH-03 Panel and report hardening: colour pattern, report escaping, CSP

## Scope

Close the two input-to-DOM gaps the review found and make the "no network, no inline script"
property of every shipped page enforceable with a Content Security Policy. Behaviour the user sees
does not change.

## Verified at the baseline

**Colour (F03).** `features/assemblies/materials/schema.rb` declares
`Fields.field("color", { "type" => "string" })` in `AUTHORED_FIELDS`; `defaults` fills `#ffffff`.
`features/zones/options/definitions.rb` has `COLOUR = { "type" => "string", "pattern" => "^#[0-9A-Fa-f]{6}$" }`.
`html/inventory_forms.js` `colorCell` reads `record.values.color || record.display.color || "#ffffff"`
and assigns it to `style.backgroundColor` and an aria label; `ColorForm` writes `colorHex(hsv)`,
lowercase `#rrggbb`. `html/column_menu.js` paints `rgb(...)` from numeric arrays, not strings.
The material library adapter (`features/assemblies/library_kind.rb`) carries `color` on the wire;
check its wire schema when changing the record schema.

**Escaping (F04).** `features/windows/export.rb` `report` builds `html` from `ReportHtml.table`
calls, then appends two raw `<p>` strings; the second interpolates
`Export::ReportHtml.h(row.fetch('construction_id'))` and `row.fetch('g_value')`, the latter not
through `h`. `features/spaces/export.rb` `report` interpolates `Export::ReportHtml.h(name)` inside
raw `<h3>`. `features/assemblies/export.rb` and `source_report.rb` use only the helpers.
`tests/window_export_test.rb` asserts the sentence "authored g-value 0 is retained exactly".

**CSP (F08).** No page has a `Content-Security-Policy` meta. `html/index.html`,
`html/agent_access/index.html` and `html/support/index.html` end with an inline `<script>` starter:
`PhComposerUI.start().panel.ready();`, `PhComposerUI.start()["agent_access/page"].ready();`,
`PhComposerUI.start()["support/page"].ready();`. `help/index.html` is generated by
`tools/help/help_page.py` and has an inline `<style>`. `html/runtime/index.html` loads one script and
a `data:` favicon. Stylesheets use `data:image/svg+xml` URLs for masks and backgrounds and no
`@font-face` or `@import`. Scripts set `element.style.*` (not governed by CSP). The runtime page
boots Pyodide, which needs `'unsafe-eval'` on Chromium below 97 (`'wasm-unsafe-eval'` arrived in
97; the floor is 88). `tools/panel_manifest.js` generates the `<script>` lists between markers and
checks them; `tools/ui-preview/index.html` mirrors the panel's styles and markup over `http://127.0.0.1`.
`tools/runtime/browser_check.py` boots the runtime page in Chromium 88 with the asset server's headers.
`tests/runtime_page_test.js`, `tests/support_page_test.js`, `tests/agent_access_dialog_test.js` and
`tests/css_selectors_test.js` read the pages or modules offline.

## Steps

### Commit 1: material colour

1. Move `COLOUR` from `features/zones/options/definitions.rb` to a shared place both features may
   use without naming each other: `core/schema_shapes.rb` (as `SchemaShapes::HEX_COLOUR`) or
   `core/records/fields.rb` (`Fields.hex_colour`). Zones keeps using it; Assemblies adopts it for
   `color`.
2. Before changing the schema: `git grep -nE '"colou?r"' starter-library tests/fixtures tools/examples`
   and confirm every value matches `^#[0-9A-Fa-f]{6}$`; fix a fixture that does not and say so in the
   PR. Check the material wire schema in `library_kind.rb` takes the same pattern, so a library file
   with a bad colour costs the row (`library.row_optional_invalid`) rather than reaching the Model.
3. `html/inventory_forms.js` `colorCell`: `var color = /^#[0-9A-Fa-f]{6}$/.test(raw) ? raw : "#ffffff";`
   before the style and aria assignments. `ColorForm` already writes a valid hex; confirm the hex
   input path validates before send (if it does not, refuse with the existing error line).
4. Tests: a case in `tests/assembly_records_schema_test.rb` (refused value, accepted mixed-case
   value); a JS case beside the existing inventory or assembly tests that renders `colorCell` with
   `"red; background-image: url(x)"` and asserts `#ffffff`.

A stored record with a colour outside the pattern now reads as `record.unreadable`, which the panel
reports per row. Ed accepted this default (PLAN.md decisions); state it in the PR.

### Commit 2: report escaping

1. `features/windows/export.rb` `report`: build both paragraphs with `Export::ReportHtml.paragraph`,
   passing the whole sentence as text (the id and the value are plain text inside it). Remove the raw
   `<p>` literals.
2. `features/spaces/export.rb` `report`: replace the raw `<h3>#{h(name)}</h3>` with a new
   `ReportHtml.heading(level, text)` helper in `export/report_html.rb`, so no feature file holds an
   HTML literal with an interpolation.
3. Add `tests/report_escaping_test.rb`: read `src/ph_composer/export/report.rb`,
   `src/ph_composer/features/**/export.rb` and `**/source_report.rb`; for every string literal that
   contains `<` and `#{`, assert each interpolation begins with `Export::ReportHtml.h(`,
   `ReportHtml.h(` or a `ReportHtml.` helper call. The test documents the rule in its comment: a
   report value reaches HTML only through `ReportHtml`. Keep `report.rb`'s own heredoc as the one
   allowed exception by listing it, since its interpolations are the helpers themselves.
4. `tests/window_export_test.rb`: keep the sentence assertion; add that a `construction_id` of
   `<b>x</b>` arrives escaped.

### Commit 3: Content Security Policy

1. Replace each inline starter with a shared `html/boot.js`:

   ```js
   /* Starts the kit and the page's entry module, named on <body data-phc-entry>. The one script a
      page may run outside the generated module list; a CSP forbids inline scripts. */
   (function () { "use strict";
     var entry = document.body.getAttribute("data-phc-entry");
     PhComposerUI.start()[entry].ready();
   }());
   ```

   `index.html`: `<body class="phc-workspace live-panel" data-phc-entry="panel">`;
   `agent_access/index.html`: `data-phc-entry="agent_access/page"`; `support/index.html`:
   `data-phc-entry="support/page"`. Load `boot.js` after the generated module list. `boot.js` is not a
   `PhComposerUI.define` module, so `tools/panel_manifest.js` must not list it; check its file
   discovery (`tests/support/panel_files.js`) and exclude it the way `module.js` is excluded.
   `tools/ui-preview/index.html` and `host.js` start the kit their own way; keep them working.

2. Add the meta as the first element in `<head>` after `charset`:

   Panel, Agent Access, Help & Diagnostics (loaded with `set_file`, origin `file://`):
   ```
   default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self';
   connect-src 'none'; form-action 'none'; base-uri 'none'; frame-src 'none'
   ```
   The blocked-run report iframe uses `srcdoc`, which inherits the parent's policy; its own content
   has an inline `<style>` and an inline `<script type="application/json">`. The JSON script is not
   executed and is not blocked; the `<style>` is. So the panel policy needs
   `style-src 'self' 'unsafe-inline'` or the report must move its CSS to a `<link>`, which a
   standalone report cannot do. Use `'unsafe-inline'` for styles on the panel page only, and say why
   in the meta's preceding comment.

   Runtime page (loaded from the loopback asset server):
   ```
   default-src 'none'; script-src 'self' 'unsafe-eval'; connect-src 'self'; img-src data:;
   worker-src 'self' blob:; base-uri 'none'; form-action 'none'
   ```
   `'unsafe-eval'` is for Pyodide's WebAssembly on the Chromium 88 floor; record that in the comment
   and revisit at a floor bump to 97 (`'wasm-unsafe-eval'`).

   Help page (`tools/help/help_page.py`): emit
   `default-src 'none'; style-src 'unsafe-inline'; img-src data:` into the generated head; links
   are navigations and need no directive.

3. Add `tests/page_csp_test.js`: for each of the five shipped pages, exactly one CSP meta, the
   expected policy string per page, no `<script>` without `src`, no `on*=` attribute, no
   `javascript:` URL. Read `help/index.html` as generated.

4. `make help` (regenerates the help page), `make panel-manifest`, `make runtime-manifest`
   (html/ changed), `make rbz`.

5. Browser evidence: `make ui-checks` (whole set) and `make runtime-browser-check`. A CSP violation
   shows in the console; `tools/ui-preview/support/browser_evidence.cjs` collects console errors,
   so a violation fails a check without a new assertion. If `'self'` does not match under the
   preview's `http://127.0.0.1` origin for some asset, fix the asset reference, not the policy.

6. Make the blocked-run report part of the browser evidence: extend
   `tools/ui-preview/preview_checks.cjs` (or add a case beside it through
   `support/browser_evidence.cjs`) so the stand-in host answers an `export.start` with a refused
   outcome carrying `report_html`, and the check reads the iframe's `h1`. `about:srcdoc` inherits
   the parent policy and is exempt from `frame-src`, which this check demonstrates rather than
   assumes.

7. A violation reporter the host can read. HtmlDialog console output never reaches the Ruby
   Console, so `boot.js` registers, on the panel page only (`data-phc-entry="panel"`), a
   `securitypolicyviolation` listener that sends one `panel.diagnostic` through the panel's `send`
   with `event: "panel_csp_violation"`, `section: null`, `error_class: "SecurityPolicyViolation"`
   and `frames: []`. Both values pass `Diagnostics`' `NAME` and `ERROR_CLASS` patterns; the
   violated directive is not sent, because the log takes no free text. The panel's existing
   `MAX_REPORTS` cap applies. Add a unit case beside `tests/panel_test.rb` or the JS panel tests
   that a dispatched `securitypolicyviolation` event produces that message.

8. Host gate (SH-03-A8). CEF's handling of `'self'` on `file://` pages and of `execute_script`
   under a CSP is not something the offline suite can show. Install the RBZ, launch a fresh
   SketchUp 26.1.188 through the bridge, and run: open the panel, apply one action and open a
   blocked-run report; open Agent Access, issue and revoke a token; open Help & Diagnostics and
   preview a report; run an HBJSON export to a scratch destination. After each panel step read
   `uv run tools/hostkit/host_bridge.py diagnostics --session <uuid> --severity warning --json` and
   confirm no `panel_csp_violation` record. The Agent Access and Help & Diagnostics pages have no
   diagnostic channel; for them the gate is that each works. Record the ledger row with the native
   acceptance skill. If any page breaks, the fallback is to name the scheme explicitly
   (`script-src 'self' file:`) and record the measurement in `context/SKETCHUP_HOST_BEHAVIOR.md`.
