# Ruby contributor readability

DATE: 2026-10-17
STATUS: In progress
AUTHOR: Ed May, BLDGTYP
ISSUE: [#198](https://github.com/bldgtyp/ph-composer/issues/198)

A repository-wide program that makes each Ruby responsibility easier for an outside contributor to
trace and change, delivered one responsibility per reviewed pull request. It covers shipping source,
tests and development tools; vendored code, fixtures, generated payloads and the private corpus are
out of scope.

This packet sits under `refactor/`, the canon's folder for cross-cutting refactors. The repository's
only declared deviation groups `features/` by roadmap phase and does not apply here.

## Read order

1. [PLAN.md](PLAN.md): authorization, invariants, stage model, delivery order and its reasons, and the
   per-stage loop.
2. [STATUS.md](STATUS.md): the program ledger. Every inventory group has a row; the exact next action
   is at its top.
3. [INVENTORY.md](INVENTORY.md): generated by [inventory.rb](inventory.rb). Every tracked Ruby file in
   scope, its group and diagnostic metrics.
4. [review-2026-10-17.md](review-2026-10-17.md): the eight-file investigation that seeded the first
   five stages. Initial evidence, not an exhaustive audit.

The rules applied are in `context/CODING_STANDARDS.md`, "Ruby readability and contributor review",
procedured by `.agents/skills/ph-composer-ruby-quality/SKILL.md` and reviewed with
`.agents/skills/ph-composer-architecture-review/SKILL.md`.
