## Scope

A01: discovery and `describe` for the Zone and Face operations return specific input, patch,
result and occurrence-reference schemas, units, and one synthetic worked example per capability.
See [A01](../review/AGENT-INTERFACE-REVIEW.md#a01-publish-usable-schemas-for-the-actual-building-operations).
Schemas come from the Phase 02 descriptors, not hand-maintained copies. Entity writes remain
owned by their feature; no generic CRUD over entity dictionaries.

## Steps

1. Reference-target `describe` returns the descriptor: values, reference fields, schema version,
   occurrence-reference schema.
2. List, make, update, classify, reverse, solve, Attached-zone save/delete: replace
   `{ "type": "object" }` inputs and outputs with specific schemas, including failure and no-op
   result shapes.
3. One synthetic worked example per capability, validated against its schema in tests.
4. Generate concise API reference pages from registrations (target under `docs/`), replacing
   any hand-written action catalog. Client-facing register, no dashes.
5. A public quickstart covering the R06 sequence.

## Source

`src/ph_composer/shell/api.rb`, `core/records/reference_target.rb`, the `zones` feature's
declaration modules from Phase 02, `docs/` for generated reference.

## Tests (write first)

1. `describe` on the Zone reference target returns values and reference schemas (today it
   returns only kind/id/owner/label).
2. Every registered building operation has non-trivial input and output schemas and at least
   one example; each example validates.
3. A synthetic client test using only discovery, `describe` and the quickstart: create a Zone,
   read Faces, classify one, preview and edit, verify affected references, recover from a stale
   revision and a lost-response retry. It references no feature Ruby constants.

## Result

Commits `71b8534` and `16bd367`.

- `API.describe` answers an entity kind with its descriptor (`Records::Descriptor#to_h`), the same
  shape a catalog kind now uses: `id`, `label`, `schema_version`, `identity_field`, `values`,
  `occurrence_reference`, `references`, plus `kind` and `owner`.
- All 22 Zone and Face operations publish closed params and result schemas and one example each.
  Record parts come from the descriptors: `Descriptor#view_schema` for a stored-record read and
  `#patch_schema` for a values patch (every field optional, null removes). Both preflight queries
  publish the shared `Export::PREFLIGHT_RESULT`. `Zones::Shapes` holds the few shared pieces.
  Results are validated at run time against these schemas, so the whole suite exercises them.
- Failure and no-op shapes: the outcome envelope is documented once at the top of the generated
  reference (status, code, effect, revision, value, affected, findings, detail, proposal_digest),
  and each result schema says what an empty result means (for example `face_ids` empty when
  nothing changed). One behavior change: an unknown Attached-zone `kind` is now refused as
  `params.invalid` by the published values schema rather than later as `validation.failed`.
- `docs/API_REFERENCE.md` is generated by `tools/api_reference/api_reference.rb`; the owning test
  `tests/api_reference_test.rb` is a `FIXTURE_OWNERS` entry, so `make fixtures` regenerates it
  and `make fixtures-check` fails when it is stale. It covers every registered operation and kind,
  foundation included, and the test refuses em and en dashes. There was no hand-written catalog to
  replace.
- `docs/API_QUICKSTART.md` covers the R06 sequence; `tests/api_client_test.rb` runs it as written
  and asserts it names no feature module.
- `context/AGENT_INTERFACE.md` points to both pages. R06 added to `cases.json`.

Tests: `api_reference_test` (4), `api_client_test` (2); full Ruby suite 634 runs on 2.7.2 and 3.2.2,
`make ci` green.

Ledger screen: A01 to A16 and R01 to R06 (`core/*` and `shell/*` patterns).
