# Documentation

Written for people: partners, contributors and users. These are the documents to hand someone who
is not building the extension, so they carry no em dashes or en dashes, no client-derived
information and no licensing negotiation.

| File | Purpose |
| --- | --- |
| [PRD.md](PRD.md) | Proposed product scope, build order, integration boundaries and exclusions |
| [PRODUCT.md](PRODUCT.md) | Agreed product behavior, carried over from the predecessor where it did not depend on designPH |
| [USERS_AND_WORKFLOWS.md](USERS_AND_WORKFLOWS.md) | Proposed journeys for consultants, colleagues, contributors and reviewers |
| [BUSINESS_MODEL.md](BUSINESS_MODEL.md) | Free and open source, optional libraries, sibling projects |
| [BOUNDARIES.md](BOUNDARIES.md) | Model ownership, export and consumers, library providers, what is outside |
| [DEVELOPMENT.md](DEVELOPMENT.md) | Implemented build/test tooling, host procedures and remaining gates |
| [AGENT_ACCESS.md](AGENT_ACCESS.md) | Access for users' agents: the in-process interface available now and the planned external connection |
| [API_QUICKSTART.md](API_QUICKSTART.md) | One scripted session from discovery to a verified edit, using only the public interface |
| [API_REFERENCE.md](API_REFERENCE.md) | Every registered operation and record kind with its schemas and an example; generated, not edited |
| [LICENSING.md](LICENSING.md) | Why AGPL, what connecting versus building in means, the DCO decision, the open UI-kit question |
| [DCO.md](DCO.md) | The Developer Certificate of Origin every commit signs off |
