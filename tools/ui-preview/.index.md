# UI preview and browser checks

Development only; nothing here ships in the RBZ. The preview is the real panel, not a mock: one set of
panel files serves SketchUp, this page and the browser checks.

## The preview page

```sh
make ui-preview
```

Open `http://127.0.0.1:8765/tools/ui-preview/`. `index.html` carries `html/index.html`'s stylesheets, body
markup and module list, generated by `make panel-manifest` between the `panel-styles`, `panel-markup` and
`panel-modules` markers; `make ci` fails while it is stale. Three things differ from the host page:

| File | Role |
| --- | --- |
| `host.js` | A stand-in host for the example feature's parts. It answers `panel.ready`, `action.invoke` (refusing a stale revision or a changed expected value, with nothing written), `preferences.set` and `export.preflight`/`export.latest` (preview-only readbacks) and `export.start` (no filesystem writes in the preview), and records every message in `previewHost.sent`. It is not the contract; `tests/panel_test.rb` checks the real host |
| `fixtures.js` | Synthetic Models chosen with `?fixture=`: `parts` (default), `empty`, `regional` (German number format), `ip` and `authoring` (two Zones with classified, incomplete and unclassified Faces, plus an Attached zone, so the tree, the legend and the palette all have something to show) |
| `../examples/foundation/editor.js` | The development-only synthetic editor, loaded after the kit starts, as the host's development entry loads it |
| `../examples/zones/example_zone_view.js` | The synthetic Zone view (Areas), loaded after the kit starts, so the Zones tab shows its view row |

The synthetic editor adds an "Example parts" section to the Zones pane, after the overview, about 129 px
tall. The shipping panel has no such section, so a height measured in the preview's Zones pane is that
much shorter than the host's at the same window size: compare against the host, not the preview, for an
exact height.

`tests/example_editor_test.js` runs the same host and editor offline.

## Browser checks

```sh
make ui-deps                                     # once: the pinned Playwright into ~/.cache/ph-composer-ui
make ui-checks                                   # every check
make ui-checks UI_CHECKS="tools/ui-preview/spaces_checks.cjs tools/ui-preview/selected_solve_checks.cjs"
```

Playwright is not a project dependency. `make ui-deps` installs the pinned version into `UI_DEPS`, outside
the repository, and the checks drive the installed Chrome; `NODE_PATH`, when set, wins. Without a
resolvable Playwright the target prints a skip line.

`support/pane_fit.cjs` is shared by the checks of panel screens, and sits outside the check glob. It sets a
panel size and waits the two frames the panel's refit takes (`setPanelSize`), reads the panel's own
scroller (`paneFacts`: sideways scroll, and for each floating control whether it is in view, reachable by
scrolling the pane alone and clear of the table header) and asserts them (`assertPaneFits`), at
`PANEL_SIZES`: 1280 x 800, 420 x 732 and the 360 x 520 minimum. A screen whose checks measure only the
page misses the panel scrolling inside itself (#179) and controls pushed under the footer or over a
header on short panels (#188).

`support/browser_evidence.cjs` is the shared collector every check runs through (`check({ name, output },
async ({ newPage, step, expect }) => ...)`). It records console errors, uncaught page errors, transport
failures (`requestfailed`) and HTTP error responses, each with the page, the current `step` label, a UTC
time and milliseconds since the run began. After the body ends it fails the run on any event the case did
not declare with `expect(kind, pattern)`, and on any declared event that never occurred: an expectation
exempts only what it matches. On failure it writes `<name>.evidence.json` (schema 1, at most 200 events,
messages and stacks clipped with an omission marker) and `<name>.evidence.txt`, a readable projection of
the same report, into the check's evidence directory. The original failure prints first; a failure to
write evidence is reported after it and never replaces it. Contexts and the browser close however the body
ends. The body returns its pass line, printed only once the browser errors are judged.
`PH_COMPOSER_BROWSER_TRACE` is `off` (default), `on-failure` or `always`, and keeps a Playwright trace per
page as `<name>.trace-<n>.zip`. The evidence comes from a local Chrome run: it is not HtmlDialog, Chromium 88
or native Undo evidence. `browser_evidence_checks.cjs` proves the collector against the real preview with a
deliberately failing inner case; `tests/browser_evidence_test.js` covers it offline.

`preview_checks.cjs` checks four panel
sizes with no sideways page scroll, a draft kept through a unit switch, an invalid entry, the New part
form's focus and Escape, a refused edit's warning, and the empty and Export panes. Screenshots go to
`PH_COMPOSER_PREVIEW_EVIDENCE`, a temporary directory by default.

A browser pass is not host acceptance: the SketchUp walkthrough is.
