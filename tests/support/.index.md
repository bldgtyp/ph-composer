# Test support

Doubles and helpers the offline suite runs the real extension code against. Nothing here ships;
nothing here belongs in `src/`.

## The SketchUp API double

`sketchup_stub.rb` is a loader. The double itself is split by namespace:

| File | Models | Refuses to model |
| --- | --- | --- |
| `sketchup/host.rb` | The load-path shim `require "sketchup.rb"` resolves against, the numeric host constants, `SketchupExtension` | Extension Manager, licensing, load order |
| `sketchup/geom.rb` | `Transformation` (composition, inverse through `Matrix`), `Point3d`, `Vector3d`, `BoundingBox` | Real geometric kernels, tolerance behaviour, curve and arc geometry |
| `sketchup/entities.rb` | Observers, attribute dictionaries, `Face`, `Edge`, `Entities`, `ComponentDefinition`, `ComponentInstance`, `Group`, `Selection` | Geometric validity, face splitting and merging, gluing, hole solving |
| `sketchup/model.rb` | `Model`, transactions and their observers, active path, `Sketchup` module functions | Undo beyond the recorded operation stack, autosave, save-as semantics |
| `sketchup/ui.rb` | Menus, commands, toolbars, `HtmlDialog`, timers, the native dialogs | Real windows, focus, the browser inside the dialog |

The predecessor's `Sketchup::Http` double served only its library connection and stays behind with
that feature.

**The default host is SketchUp 23.0.0**, the support floor, so what a test sees by default is what
the extension must support. A test that needs another host sets `Sketchup.version_value`.

**Three deliberate deviations from the host API** are pinned by
[`../sketchup_stub_deviations_test.rb`](../sketchup_stub_deviations_test.rb), each beside the
evidence that makes the naive behaviour a lie: `read_default` returning nil for a string with a
double quote, `open_file` reusing the active document, and `Transformation#inverse` going through
`Matrix`. The measured facts behind them are in
[`context/SKETCHUP_HOST_BEHAVIOR.md`](../../context/SKETCHUP_HOST_BEHAVIOR.md).

`sketchup_stub_test.rb` covers the double's own transaction, undo and timer behaviour. None of it
replaces the fresh-process host gate.

## Helpers

| File | What it provides |
| --- | --- |
| `fixture_files.rb` | `write_fixture` and `assert_fixture` behind the `make fixtures` mode; see DEVELOPMENT.md "Fixtures and coverage" |
| `record_fixtures.rb`, `test_feature.rb` | Synthetic record kinds and a feature built from the public registration calls |
| `units_vectors.json` | Shared SI/IP conversion vectors, read by both the Ruby and the JavaScript unit tests |
| `face_geometry_pure.rb` | FaceGeometry's rules in a bare Ruby process with no SketchUp and no stub; `face_geometry_test.rb` runs it as a subprocess |
| `zone_child_fixture.rb` | A second feature owning records inside Zone occurrences, built from public contracts, for the Zone transition tests |

## The panel's doubles

| File | What it provides |
| --- | --- |
| `dom_stub.js` | Enough of Element and Document for the ES2020 panel code. Its header lists the selector forms it supports; anything else returns false rather than half-matching. It does no layout |
| `panel_files.js` | What counts as a shipped panel script, for the manifest, the coverage runner and the agreement tests; the runtime page's scripts (`html/runtime/`) are listed apart, since the panel never loads them |
| `panel_source.js` | One way to load panel source into a test's vm context, and `start(context, roots, stubs)`, which builds only the modules a test names plus their declared dependencies |
